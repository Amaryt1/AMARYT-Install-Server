# Security model

Use trusted HTTPS for both the API and the manifest/package endpoints. The device must authenticate the API origin with normal platform certificate checks. Keep private bearer credentials in Keychain, unique per client or user; never distribute a global token in a public app. Administrative settings and credentials are managed on the host. Rotation requires changing API_CLIENTS and restarting. The server has no P12, private-key, certificate password or signing API. The signed IPA may include the public provisioning material embedded during signing.

Source validation uses exact allowlisted hostnames, HTTPS on port 443 and a bounded DNS lookup. All A/AAAA answers must be public; every redirect is validated again. A HEAD request connects directly to the validated IP with the original hostname for TLS, SNI and Host. No client Authorization header, cookies or other credentials are forwarded. Configure a restrictive egress firewall and allowlist only trusted CDNs. Device downloads should independently apply HTTPS and redirect policy, including after a server-side probe.

Uploads are streamed with declared and actual byte limits. Unique private filenames, atomic publication, owner checks, rate and capacity limits, expiring 256-bit capabilities and cleanup restrict access. Keep data on encrypted storage with quota, one exclusive backend process and no backups. Proxy/CDN access logging, tracing and caching must exclude full capability URLs. Caddy's sample leaves access logging disabled. Application failure logs contain a route template, status, code and request ID.

Archive inspection requires one main app with Info.plist, embedded.mobileprovision and _CodeSignature/CodeResources, bounded entry count and a matching bundle identifier/build from the actual plist. This is structural validation. It does not attest the CMS signature, profile eligibility, entitlement compatibility or device trust. iOS performs those checks. Production end-to-end testing requires a known eligible signed IPA and a physical iOS device.

OTA metadata was implemented from the Apple deployment model. The reference projects ForgeSign-iOS and xykong/itms-services were inspected for flow and manifest shape. No source code, templates, binaries or signing assets were imported from them. See [Apple deployment guidance](https://support.apple.com/guide/deployment/depce7cefc4d/web).
